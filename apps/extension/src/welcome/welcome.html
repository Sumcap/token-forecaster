What the three numbers mean

  • The draft. Counted in your browser with a character heuristic, labelled estimate. Turning on verified counting makes it an exact Anthropic count.
  • The reply. A band, not a needle. The forecaster has no single answer to give, so it draws the range and fades it outward where it knows less.
  • The conversation. Only what the page renders while the chip is active. It is prefixed ≥ because it cannot see the system prompt, attachments, tools, or memory.

Where it runs

On claude.ai/code, and nowhere else by default. The profile was fitted on Claude Code agent traffic, so that is the surface it describes. On the chat surface the panel says it is out of domain. The confidence reads low on both surfaces, because the profile was fitted on one person’s history.

What leaves your browser

Nothing by default. Verified counting is one optional path: only after you enable it and paste your own API key do the draft text and model id go to Anthropic's count_tokens endpoint. The two separate contribution choices below are the other optional path and send only the fields they describe. Raw conversation text is never contributed. Your claude.ai session, cookies, and history are never touched.

Help improve it (optional)

Forecasting works with both choices off. Each box is separate and nothing is collected until you check it. Prompt text, reply text, URLs, Claude account information, cookies, and API keys are never included. Read the full packaged privacy notice.

The profile behind the forecast

Reading the bundled profile...

Nothing is learned in your browser. The profile is frozen at build time and it does not adapt to you as you use it. Training it on your own local Claude Code history is not available yet; when it is, this page will say so and the panel will name which profile it used.
